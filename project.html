PDF智转 项目说明文档

一款完全在本机完成计算的 PDF 工具箱。所有 PDF 处理逻辑都在 Rust 侧执行， 以内嵌的 PDFium 作为唯一引擎，前端只负责界面与任务编排。支持合并、拆分、旋转、 PDF 转图片、图片转 PDF 五大功能。

技术选型与框架

桌面壳用 Tauri 2（体积远小于 Electron，且能直接调用 Rust），核心计算全部下沉到 Rust + PDFium。

🖥️ 桌面框架

Tauri 2 Rust edition 2024 rust-version 1.90

系统 WebView 渲染 UI，Rust 主进程负责文件与 PDF 计算。窗口 titleBarStyle: Overlay，自定义拖拽区。

⚙️ PDF 引擎

pdfium-render 0.9.5 chromium/8125 thread_safe

唯一 PDF 引擎，运行时动态绑定 libpdfium.dylib（不静态链接）。合并 / 拆分 / 旋转 / 栅格化 / 图片建页全部共用它，保证输出行为一致。

⚛️ 前端

React 19 TypeScript ~6.0 Vite 8 Tailwind CSS 3.4

状态管理 zustand 5；路由 react-router-dom 7（HashRouter）； 国际化 i18next 23 + react-i18next 15；图标 lucide-react； 拖拽排序 @dnd-kit；类名合并 clsx。

🔌 Tauri 插件

dialog store opener notification log single-instance

文件/目录选择、设置持久化（settings.json）、打开产出、完成通知、日志、单实例。

功能清单

五大处理功能 + 设置页 + 关于页。全部由 features/registry.ts 的功能注册表统一驱动。

◈ 合并 PDF organize

多份 PDF / 图片按列表顺序合并为一个 PDF。支持拖拽排序、首页缩略图顺序预览条。选项：页面尺寸、方向、图片适配、页边距、图片 DPI、压平注释。加密文档可逐个解锁。

◈ 拆分 PDF organize

四种模式：每 N 页一份 / 每页一份 / 按页范围表达式拆分 / 提取指定页。可选打包为 zip；非打包时按 {stem}_part001_p1-3.pdf 规则命名。

◈ 旋转 PDF organize

按 90 / 180 / 270 度旋转指定页范围，缩略图网格实时预览旋转效果。支持「原地覆盖」模式（此时隐藏输出目录选择）。

◈ PDF 转图片 convert

把 PDF 页面栅格化为图片。选项：页范围、DPI、格式（png/jpg/webp）、质量、最长边限制、是否打包 zip。文件名按 {stem}_p001.png 规则生成。

◈ 图片转 PDF convert

多张图片按顺序合成 PDF，支持拖拽排序。选项：页面尺寸、方向、图片适配、页边距、DPI。受 asset 协议 scope 限制，不做原图预览。

⚙️ 设置 & ℹ️ 关于 system

设置：语言 / 主题（light·dark·system）/ 输出策略（remember·ask·fixed）/ 图片默认值 / 完成通知 / 缩略图尺寸 / 清理缓存 / 恢复默认。关于：版本、Tauri/PDFium 信息、引擎重新检测、开源许可清单。

贯穿全局的交互能力

  • 全局拖拽：拖入文件自动按扩展名匹配功能；单一匹配直达，多匹配弹出 FeatureChooser；顶部 DropOverlay 实时预告目标。
  • 任务中心：右下角 TaskDrawer 汇总运行中/已完成/失败任务，实时进度、取消、产出打开/定位、相对时间。
  • 加密 PDF：列表中就地输入密码解锁，探测失败静默不阻塞整批添加。
  • 页范围表达式：all/*、odd/even、first/last、first:N/last:N、1,3-5,8，前端即时校验「将影响 N 页」，后端为最终展开。
  • 双语 i18n：zh-CN 默认 + en-US，zh-CN.ts 是形状来源，缺 key 编译期报错。

前端设计要点

功能注册表（扩展核心）

FeatureDefinition 是唯一扩展点：路由、侧边栏分组、首页卡片、全局拖拽匹配、选项表单、请求构造全部由它驱动。新增功能 = 写一个 features/<id>/meta.ts + 在 FEATURES 数组加一行，无需改动任何布局或路由代码。

  • Page 可选：缺省落到 GenericFeaturePage（零页面代码即可上线简单功能）；需要额外呈现（合并的顺序预览、旋转的实时预览）才写自定义页。
  • buildRequest(files, values, context) 把界面状态翻译成后端 TaskRequest，kind 直接等于 feature.id，中间没有映射表。

统一控制器 useFeatureController

把「来源列表 + 选项值 + 输出目录 + 任务运行」组合成一个对象，所有功能页共用：

Hook职责
useSourceFiles去重、按扩展名分流、stat_paths 补体积、逐个 probe_document 探测、密码解锁
useOutputPicker按输出策略解析目录；ask 模式现场弹框，取消则不悄悄写默认目录
useTaskRunner把后端事件绑定到本次运行的记录上，处理 taskId 晚于进度事件到达的竞态
usePdfThumbs / useFirstPageThumbs页面缩略图网格 / 合并页首页顺序预览条，逐个回填、防竞态
useTheme / useAppBootstrap主题应用与语言切换 / 启动时加载设置、任务、引擎状态、通知权限

状态与持久化

  • store/settings.ts：plugin-store 落盘，300ms 防抖；磁盘值逐字段 sanitize 后与默认值合并；ready 之前不写盘，避免默认值覆盖旧配置。
  • 主题：Tailwind darkMode: "class"，useTheme 只在 <html> 增删 dark；颜色令牌集中在 CSS 变量，组件不写 dark: 前缀。
  • 窗口拖拽：靠 data-tauri-drag-region 属性（非 Electron 的 -webkit-app-region）。

后端设计要点

任务模型

  • run_task(request, out_dir, password, notify) 是唯一入口：创建 TaskRecord、在 tokio 阻塞池执行对应 pdf::<op>、进度经事件推给前端、结束写回记录。
  • 取消走 CancelToken（HashMap<taskId, token>），各功能在页/文件循环里检查令牌。
  • 历史记录保存在内存（上限 50 条），不持久化：任务中心是「本次会话」视图，重启清空是预期行为。

事件契约

事件payload用途
task:progress{taskId, feature, current, total, message}进度条与状态文字
task:log{taskId, level, message}非致命告警
task:finished{taskId, feature, outputs, elapsedMs}产出列表、通知
task:failed{taskId, feature, error, elapsedMs}错误展示（error.kind 映射 i18n）
事件 payload 定义在 events.rs，前端镜像在 lib/tauri.ts + store/tasks.ts。改事件必须两边同步。

错误模型

AppError 用 serde 邻接标签序列化为 { kind, message }，kind 是封闭枚举：pdfiumNotFound / passwordRequired / pdf / io / image / archive / invalidParams / range / unsupported / cancelled / internal。前端把 kind 映射成 i18n key，message 仅作补充细节。

引擎动态加载（pdf/engine.rs）

libpdfium 运行时按顺序动态绑定，init() 幂等：

  1. 环境变量 PDFIUM_PATH
  2. Tauri resource_dir（打包后 *.app/Contents/Resources/libpdfium.dylib）
  3. 开发期 src-tauri/binaries/libpdfium.dylib
  4. 可执行文件同级目录
  5. 系统已安装的 libpdfium

失败时返回 PdfiumNotFound(searched) 带上全部搜索路径，关于页原样展示，用户放入 dylib 后点「重新检测」（reload_pdfium）即可，无需重启。

缩略图缓存

渲染结果以 PNG 落在 app cache 目录，缓存键为 (source, max_px)；前端用 convertFileSrc 生成 asset:// URL 直接 <img> 读取，避免 base64 过 IPC。ThumbOut.page 为 0-based，展示时 +1。

安全模型

  • CSP：default-src 'self'，图片额外允许 asset: / blob: / data:，连接允许 ipc: 与 asset:。
  • asset 协议 scope 仅 $APPCACHE/**：缩略图可读，用户任意文件不可读。
  • 打开产出文件走后端命令 open_path（JS openPath 需要 allow-open-path + 路径 scope，而产出目录用户任选无法提前枚举）。
  • 最小权限：capabilities/default.json 只授予 core/dialog/opener/store/log/notification 的默认集合 + allow-start-dragging + allow-set-title。
  • 本地优先：无任何网络上传，文件全部在本机处理。

可优化 / 待完善的地方

按优先级列出后续可推进的改进项。

1
代码签名与公证高

当前 ad-hoc 签名，分发给其他 Mac 用户会被 Gatekeeper 拦截。接入 Apple Developer ID 签名 + notarytool 公证，并考虑 Sparkle/Tauri updater 做自动更新。

2
缺少前端自动化测试高

前端只有 typecheck，没有单测/E2E。建议引入 Vitest 覆盖 lib/pages.ts、lib/errors.ts、store 逻辑，以及 Playwright 覆盖关键交互链路。

3
大文件 / 多页任务的进度与内存中

栅格化高分辨率整本 PDF 时内存占用可能较高。可评估流式写出、分页释放、以及对超大任务的显式上限/提示。

4
跨平台支持中

目前只产出 macOS。PDFium 下载脚本与 bundle 配置需补 Windows（.exe/NSIS）与 Linux（AppImage/deb）目标，图标也要补 .ico 的实际生成。

5
任务历史持久化中

任务记录仅在内存（上限 50 条），重启即清空。若产品希望「最近处理」可回溯，可落盘到 store 或 SQLite。

6
图片转 PDF 的原图预览低

受 asset scope 限制无法预览用户原图。可评估把用户选择的图片渲染一份缩略图到 $APPCACHE 再预览（与 PDF 缩略图同机制）。

7
文档补全低

已有 docs/ARCHITECTURE.md 与 docs/ADD-FEATURE.md，尚缺 docs/BUILD.md 与顶层 README.md；建议把本文档的构建/打包章节沉淀进去。

8
可访问性与细节低

补充键盘导航（拖拽排序的键盘等价操作已有 sortableKeyboardCoordinates）、Aria 标签完整性、以及深色/浅色对比度审计。
